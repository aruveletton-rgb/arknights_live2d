证据：本计划、当前工作区状态、阻塞清单。

### N1 资源与运行时审计

用户确认：

- 样例模型来源、角色名称、文件清单、版本、SHA-256。
- Cubism SDK/Core 或 Web SDK 的版本、使用条款、是否允许随安装包发布。
- 运行时路线：官方 Web SDK 直接渲染，或经许可的 Pixi 集成；选择依据是 Electron `file://`、Windows 包、资源释放和动作/物理支持。
- 许可不允许再分发时，是否接受“本机导入、发布包不含模型”的交付方式。

证据：来源页、许可摘录、哈希、SDK 版本、分发结论、依赖锁定文件。

### N2 供应商资格审计

用户确认：

- 是否由用户在安全环境输入或配置临时凭据；凭据不进入聊天、仓库、日志和审计文件。

- Azure Speech 是否为目标区域 F0；记录 STT/TTS 语言、声音 ID、共享免费额度和剩余额度。
- 额度耗尽行为固定为拒绝受影响请求，不自动升级或切换到未批准的付费层。

证据：脱敏控制台截图/导出、条款链接、合成测试记录、错误和用量记录。

### N3 数据服务与合同审计

用户确认：

- 账号：管理员创建/禁用/重置；不开放自助注册；密码哈希和会话失效规则。
- 历史：每账号最近 30 天；过期记录不展示、不检索；清理和备份行为。
- 记忆：只有用户明确要求“记住”才保存；查看、编辑、删除立即生效。
- 录音/音频：原始录音不纳入聊天历史；短期缓存、备份保留、删除传播和恢复语义。
- 日志：只保留 request_id、耗时、错误和用量，不记录密码、令牌、完整录音和记忆正文。

证据：版本化 API 合同、SQLite/数据结构迁移说明、越权负例、删除和恢复演练、脱敏日志。

### N4 实机与部署审计

- 是否授权远程只读盘点、部署、回滚和健康演练；任何重启或可能中断服务的动作单独记录。

证据：设备矩阵、端口盘点、证书链、健康检查、内存/CPU/磁盘/队列记录。

## 5. 执行顺序与任务

### P0-1 依赖和样例包锁定（解除 B1）

**前置**：N0、N1 通过。  
**动作**：

1. 建立 `audit/thread_a_next_step_manifest.json`，记录资源、SDK、许可证和哈希。
2. 在隔离的技术试验目录验证模型包入口、纹理、动作、表情、物理和参数映射。
3. 选择 Web SDK 直接渲染或 Pixi 集成；只锁定实际可安装、可打包和许可允许的组合。
4. 实现模型加载/释放、缺失资源错误、样例待机、点击、动作、表情和音频口型。
5. 将模型和 Core 放在允许的位置；禁止把未授权二进制放入 Git 或发布包。

**证据**：真实模型截图/录屏、动作/表情矩阵、资源释放记录、安装包资源清单、样例版权说明。  
**停止条件**：资源或 Core 许可不清、模型包损坏、`file://` 资源加载失败、重复加载后内存/对象不释放。

### P0-2 供应商资格与最小真实链路（解除 B2）

**前置**：N2 通过；使用合成测试信息。  
**动作**：

1. Groq：验证中/日文文本、角色风格、短记忆检索和结构化提醒草稿；记录首字延迟、完整延迟、失败率、429 和实际速率限制。
2. Azure Speech：验证中/日 ASR 短句、静音/噪声、普通预置音色、长句和数字；记录识别错误、首音、完整时长和 F0 余额。
3. 串联 ASR → LLM → TTS → 播放/口型；每次请求带 request_id、language 和超时。
4. 关闭 TTS 做零合成调用验证；取消请求后确认不播放旧音频；供应商 401/429/503/超时均转为分项降级。

**证据**：不含密钥的请求摘要、音频结果、耗时表、用量/额度、故障矩阵。  
**停止条件**：资格不满足、ZDR/F0 不可证实、服务地区或额度不符合、效果/延迟未达到用户确认门槛。

### P0-3 共用账号、历史和记忆服务（解除 B3）

**前置**：N3 通过；服务端文件级变更清单先审计。  
**动作**：

1. 锁定 `/api/auth/login`、会话失效、`/api/chat`、历史查询/删除、记忆 CRUD 的 JSON 合同。
2. VM-1 使用 SQLite 起步：账号、会话、消息、记忆、提醒同步边界分表；每个记录绑定服务端 user_id。
3. 密码使用标准密码哈希；客户端不提交任意 user_id；服务端从会话确定身份。
4. 历史查询实时排除超过 30 天的消息；删除和记忆修改立即影响后续检索。
5. 记忆写入必须有明确确认字段；供应商只接收当前请求所需的最小上下文。

**证据**：迁移说明、双账号隔离、注销/过期、越权拒绝、历史清理、记忆删除和日志脱敏结果。  
**停止条件**：越权、删除后仍可检索、恢复复活已删数据、日志泄露正文/凭据。

### P0-4 真实桌宠联调与错误闭环

**前置**：P0-1、P0-2、P0-3 通过各自 N5。  
**动作**：

1. 接入真实模型资源和真实 ASR/LLM/TTS 配置；Mock 与真实模式显式分栏。
2. 完成中文/日文切换、文本输入、按住说话、字幕、音频播放、口型和错误提示。
3. 测试快速多轮请求、取消、网络抖动、旧任务覆盖、语言切换和账号切换。
4. 真实链路失败时保留文本输入和模型互动；只暂停受影响功能。

**证据**：两种语言端到端录屏、请求/响应摘要、故障矩阵、账号隔离和真实/Mock 标记。

### P0-5 干净 Windows 验收（解除 B4 的客户端部分）

**前置**：P0-1、P0-4 通过。  
**动作**：

1. 在无 Node/Python 开发环境的 Windows 上安装 NSIS 包，验证启动、透明置顶、托盘、关窗、退出和卸载。
2. 解压 portable 包，验证模型/声音资源、设置、提醒和网络错误行为。
3. 测试多显示器、DPI 变化、睡眠恢复、重启错过提醒、麦克风拒绝和音频设备切换。
4. 记录 CPU、RSS、帧率、首字、首音、完整回复延迟和长跑趋势；门槛由用户依据报告确认。

**证据**：设备信息、安装/卸载日志、截图/录屏、包哈希、性能表、已知限制。

### P0-6 HTTPS/VM 部署与故障演练（解除 B4 的服务部分）

**前置**：N4 通过；用户明确授权远程操作。  
**动作**：

1. 只读盘点 VM-1/VM-2 的进程、端口、磁盘、内存和现有配置。
2. 确认 VM-1 入口、VM-2 内部通信、DNS、80/443、证书续期和公网端口门禁。
3. 部署前先 `dry-run`，再启动受限服务；公网请求必须带非空认证令牌。
4. 停止 VM-2、停止 ASR/TTS、断网、恢复服务，验证健康状态、降级和回滚。
5. 记录请求体上限、超时、队列上限、429、健康探针不消耗真实额度。

**证据**：脱敏配置、证书链、健康检查、端口暴露结果、故障演练和回滚记录。  
**停止条件**：证书不受信任、公网端口越界、VM 内存不足、认证绕过、回滚不可用。

## 7. 交付状态规则

| 状态 | 条件 |
|---|---|
| `pass` | 真实模型、真实链路、账号/数据隔离、实机和部署验收均有证据 |
| `candidate` | 本地功能和 Mock 通过，但仍有用户接受的未验证项，不得作为稳定版宣称 |

| `unverified` | 已设计或已实现，但当前没有足够的真实运行证据 |
